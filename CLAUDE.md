# Køkken

An Eleventy-powered cooking notebook: recipes, cocktails, grill guides and smoke guides. Content is
plain Markdown with structured front matter, rendered through Nunjucks layouts and styled with
Tailwind. Everything the site shows comes from front matter, not from prose.

## Commands

| Command | What it does |
|---|---|
| `npm install` | Install deps (Node 18+). |
| `npm run dev` | Eleventy at `localhost:8080` + Tailwind watch, in parallel. |
| `npm run build` | Clean `_site/` and build Eleventy + minified Tailwind. |
| `npm run preview` | Build, then serve `_site/` at `localhost:5000`. |

There is **no test suite**. `npm run build` is the only gate — a change is verified by building
clean and eyeballing the affected page.

## Deployment

Live at **https://kokken.pages.dev** on **Cloudflare Pages**. Pushing to `master` is the deploy:
Cloudflare is wired to the GitHub repo (`apodacaa/kokken`), builds on push, and serves `_site/`.
To publish a content change, commit and `git push origin master` — nothing else.

**The repo contains no evidence of any of this, and that is expected.** There is no
`wrangler.toml`, no `.github/workflows/`, and `_site/` is gitignored; the build command, output
directory and Node version live in the Cloudflare dashboard. Grepping the repo for the host finds
nothing. Do not conclude from that absence that the site is unconfigured or broken — verify
against the live URL instead.

Two files invite exactly that wrong conclusion:

- `.pages.yml` is **not** a deploy config. It configures [PagesCMS](https://pagescms.org), a
  browser-based Markdown editor for `content/`. The name collides with Cloudflare Pages and
  GitHub Pages; it is neither.
- `.nojekyll` is a leftover from an abandoned GitHub Pages attempt and does nothing under
  Cloudflare.

**GitHub Pages was disabled on 2026-09-20** and must not be re-enabled. It had been configured to
serve the repo root on `master`, so `apodacaa.github.io/kokken/` returned 404 for every page while
happily serving raw `.md` source, and every push re-deployed the same broken output. Cloudflare
supersedes it.

**Every URL on the live site returns HTTP 200.** Cloudflare is serving the home page as a
catch-all fallback for unmatched paths, so `kokken.pages.dev/anything-at-all/` answers 200 with the
home page. A status code therefore proves nothing — to check whether a page really deployed, fetch
it and grep the body for content unique to that page.

Pushing uses `gh` for credentials. `gh auth setup-git` was run on 2026-09-20, so a bare
`git push origin master` works. **Caveat:** it wrote gh's *version-pinned* mise path into
`~/.gitconfig` (`.../installs/gh/2.100.0/...`), so a gh upgrade under mise will break the helper
and pushes will fail again with `could not read Username for 'https://github.com'`. Fix by
re-running `gh auth setup-git`, or one-shot with
`git -c credential.helper='!gh auth git-credential' push origin master`.

## Never hand-edit

- `_site/` — build output, wiped by `npm run build`.
- `assets/styles.css` — generated by Tailwind from `assets/input.css`. Edit the input file.

## Content model

Content lives in `content/{recipes,cocktails,grill,smoke}/*.md`. One file per item. Collections
(`recipes`, `cocktails`, `grillGuides`, `smokeGuides`) are globbed from those directories in
`.eleventy.js` and sorted alphabetically by `title`. Indexes, nav and prev/next update
automatically — never hand-maintain a list of items.

Every file needs `title`, `slug`, `layout` and `permalink`. `slug` must be unique within its type
and must match the `permalink`.

### Recipes (`layouts/recipe.njk`, `/recipes/{{ slug }}/`)

Required in practice — all 61 files have them: `ingredients`, `steps`, `pairings`.

- `ingredients` — a list of `{ section, items }` objects. Use `section: _main_` for ingredients
  with no sub-heading; the template suppresses that heading specially. Named sections
  (`Marinade`, `Sauce`, `Assembly`, …) render as sub-headings. Every existing recipe uses the
  sectioned form; a flat list of strings also renders, but don't introduce one.
- `pairings` — `wine` and/or `beer`, each a list of `"Name – why it works"` strings. Rendered
  joined with `; `. Spelled `pairings` (the template also accepts the typo `parings`; don't use it).
- `steps` — ordered strings, rendered as the method.
- `notes` — optional, a single string rendered as one paragraph. Not a list. Rare (3 of 61).
- `references` — optional, `{ slug, title, type }` where `type` is `recipe | cocktail | smoke |
  grill`. `type` picks the URL base, so a wrong `type` silently produces a dead link. Rare (3 of 61).

### Cocktails (`layouts/cocktail.njk`, `/cocktails/{{ slug }}/`)

Same layout partial as recipes. `ingredients` is a **flat list of strings** here, not sections.
`steps` are short method lines (shake / stir / build / garnish). `notes` and `references` behave as
above and are rare. No `pairings`.

### Smoke guides (`layouts/smoke.njk`, `/smoke/{{ slug }}/`)

- `phases` — required, a list of `{ name, temperature, duration, doneness, wood }`. `name` is the
  stage (`Smoke`, `Wrap`, `Rest`, `Sear`). **`wood` belongs inside the phase that uses it**, not at
  the top level, so the UI shows it beside temp and time. Individual keys within a phase are
  optional and are skipped if absent.
- `amount` — optional display size, e.g. `"10–14 lb"` (10 of 25 files).

### Grill guides (`layouts/grill.njk`, `/grill/{{ slug }}/`)

All four body fields are optional and render only when present: `amount`, `gas`, `charcoal`,
`done`. `gas` and `charcoal` are time/heat guidance (`"6–8 min direct medium heat"`); `done` is the
target internal temperature. Most files have all four.

## Conventions

- **Units: US first, metric in parentheses.** `24 oz (700 ml)`, `2 cups (200 g)`, `400°F (200°C)`.
  Cocktails use oz first with cl in parentheses: `1 1/2 oz (4.5 cl) gin`.
- Use an en dash for ranges: `225–250°F`, `4–6 hr`.
- Quantities are plain fractions (`1/2`, `1 1/2`), not unicode fractions.

## Traps

**Tags are disabled. Do not add a `tags:` field.** `_data/site.json` sets `features.tags: false`,
every tag block was stripped in commit `7756b04 removed tags`, and zero content files carry one.
The `tagList` / `tagsMap` / `tagsWithCounts` collections and the `tags/` pages are all dormant
behind that flag. Adding one produces front matter that renders nothing. (The README used to
document tags at length; it was corrected on 2026-09-20 and now agrees with this file.)

**Recipe and cocktail body text is never rendered.** `_includes/partials/entry.njk` does not output
`content` at all, so prose written below the front-matter block in a recipe or cocktail silently
disappears. Put it in `notes` instead. Smoke and grill layouts *do* render the body, but prefer
structured fields there too so guides stay scannable.

**Prev/next navigation only exists for recipes and cocktails** (`entry.njk` looks up
`collections.recipes` / `collections.cocktails` by layout). Smoke and grill pages have none.

**`references` renders under the heading "Related Recipes"** whatever the target type, so a
reference to a smoke guide still appears under that heading.

## Layout map

`_includes/layouts/` holds one layout per type plus `base.njk`, the index layouts and `home.njk`.
`_includes/partials/entry.njk` is the shared recipe/cocktail renderer and is where most rendering
logic actually lives — check it before editing `recipe.njk` or `cocktail.njk`, which are thin
wrappers. `recipe-steps.njk` renders the method for both.
